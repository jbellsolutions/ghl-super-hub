# Operating contract

The outcome is a working business process in the selected HighLevel account.
A package, imported resource, draft or successful API response is an intermediate state.

Before execution establish location, objective, audience, environment (test/live),
resource identity and requested final state. Infer routine choices from the task;
ask only for missing decisions that change the result. Existing authorization
covers its ordinary implementation. Building this toolkit does not itself authorize
launching campaigns, collecting money or changing an unrelated production account.

Select the supported API for data work; select the dashboard for authoring not
exposed in the official catalog. Public API scope coverage and account plan/role
availability are independent. A dashboard-only action may still need an account
upgrade or a different role; no token can override that.

Persist a task record with location ID, resource IDs, pre-change state, desired
state, executed steps, verification evidence, and remaining issues. Do not put
credentials, raw personal data, session cookies or MFA secrets in task records.
Screenshots may contain customer information: keep them in the tenant's private store.

Read back configuration after writes. For end-to-end processes use a test contact
and confirm events in workflow history, conversations, submissions, orders or
membership activity as appropriate. Distinguish administrator previews from the
customer experience. Finish with resource IDs/URLs, observed results, and blockers.
Never report a live verification you did not perform.

If an integration gap remains, document the desired input/output and which layer
can fulfill it: native UI, reusable snapshot, workflow webhook/custom action, or an
external service. Do not label undocumented reverse-engineered endpoints supported.
